- 取り組んだレベル：基礎 
- やったこと（変更したファイル・設定・処理、または設計した取得方法）：config.py の `RAG_TOP_K` を既定の `5` から `2` に変更し、同じ質問を行って変更前後を比較した。
- 比較した質問と、固定した条件（モデル・対象資料など）：
質問：「第3回の例では、コンパクションとセッションをまたぐメモリはどう違いますか。日々のメモはすべて長期メモリに入りますか」
モデル：`gemini-3.1-flash-lite`（`AIE_MODEL=gemini-3.1-flash-lite`）
- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：
- 変更前（`RAG_TOP_K = 5`）
    - `--trace`：`search_materials({'query': 'コンパクション セッション メモリ 長期メモリ'})`（1回）
    - 回答と根拠：第3回・PDF p.13, 38, 39, 40, 65 を引用。コンパクションとセッションをまたぐメモリの違いに加え、p.40 の OpenClaw（dreaming による選別）の具体例まで正確に回答できた。
    - 時間・トークン・費用：4.45 秒 ／ 入力 2,495・出力 654 tokens（モデル応答 2 回）／ $0.001605 USD
  - 変更後（`RAG_TOP_K = 2`）
    - `--trace`：`search_materials({'query': 'コンパクション セッションをまたぐメモリ 長期メモリ'})`（1回）
    - 回答と根拠：第3回・PDF p.38, 65 のみを引用（p.13, 39, 40 が欠落）。後半の「日々のメモはすべて長期メモリに入るか」について「記載はありません」と答え、p.38 の一般論のみの説明になった。
    - 時間・トークン・費用：15.52 秒 ／ 入力 1,495・出力 505 tokens（モデル応答 2 回）／ $0.001131 USD
- 改善した例と、残る失敗・制約：
取得件数を減らしたことで、入力トークン数が2,495 → 1,495 に減少した。生成 API の推定費用が約 $0.001605 → $0.001131 USDになった。
- 気づき・疑問：
RAG_TOP_K` の設定はコスト削減になるが複大きな質問ほど重要な根拠を取りこぼしやすいと実感した。
